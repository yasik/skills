# Index of the Google developer documentation style guide

This index mirrors the official guide's navigation at https://developers.google.com/style and maps every page and section to the local reference that packages it. Content is adapted from the guide under CC BY 4.0; the official pages provide editorial source context. Bundle instructions and repository conventions control workflow, scope, and authorization.

The `Local` column links into the packaged references. Section rows link to the official anchor first and the local heading second. Introduction pages are summarized at the end of this file rather than packaged separately.

## Introduction pages

### About this guide

<https://developers.google.com/style>

Editorial guidelines for clear, consistent technical documentation for developers and other technical practitioners. Reference hierarchy: (1) project-specific style, (2) this guide, (3) third-party references: Merriam-Webster for spelling, *The Chicago Manual of Style* (17th edition) for nontechnical style, the Microsoft Writing Style Guide for technical style. Established usage (your organization's docs, Google Ngram Viewer) can settle open questions. Other guides worth consulting but not part of Google style: Apple Style Guide, Red Hat supplementary style guide. Android- and Google Cloud-specific guidance is marked with logos in the official guide; the packaged references label it in text. "Break the rules": these are guidelines, not rules. Depart from them when doing so improves the content, and be consistent about it throughout the document.

### Highlights

<https://developers.google.com/style/highlights>

The one-page summary. The skill's core rules in `SKILL.md` are a superset of it: conversational tone; don't pre-announce; descriptive link text; write accessibly and for a global audience; second person; active voice; American spelling; conditions before instructions; word list; sentence case; numbered lists for sequences, bullets otherwise, description lists for pairs; serial commas; code font for code; bold for UI elements; unambiguous dates; alt text; high-resolution or vector images.

### What's new

<https://developers.google.com/style/whats-new>

The changelog. The packaged references reflect the guide as of the July 7, 2026 update (the newest entry when they were captured). Notable recent changes: "do the following" recommended for list introductions and firmer list-punctuation consistency (April 2026); spelling guidance folded into the word list and phone numbers formatted with dashes (January 2025); consolidated hyphenation guidance (October 2024); binary versus decimal units such as GiB versus GB (August 2024); code omissions shown with a comment rather than an ellipsis (January 2024); external-link icons dropped in favor of stating the destination in text (November 2023).

### Philosophy of this guide

<https://developers.google.com/style/philosophy>

The guide exists for internal consistency, not as an industry standard. It doesn't try to be comprehensive, to replace other style guides, to teach writing, or to give legal advice. It deliberately omits most rationale: many choices come from accessibility, localization, and comprehension needs; many are one workable option among several chosen for consistency; and explanations get in the way of quick lookups.
